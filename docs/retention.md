# Closed-task retention

`bin/fm-retention.sh` reclaims disposable task artifacts only after the backlog proves that their task closed and the configured retention age has elapsed.
Preview is the default.
Run `bin/fm-retention.sh` to print every proposed removal, its allocated size, every retained item, and the reason it was retained.
Run `bin/fm-retention.sh --apply` only when that exact preview is acceptable.

## Retained and removed material

The age-based sweep covers SDev task workspaces, task-owned treehouse worktrees, direct `state/` task records including task-owned watcher markers, and `data/<id>/report.md`.
The captain deliberately chose report deletion, so investigation reports older than the retention window are expected to disappear.
`data/<id>/brief.md` is never a candidate.
The top-level durable files `data/backlog.md`, `data/captain.md`, `data/captain-shared.md`, `data/learnings.md`, `data/projects.md`, and `data/secondmates.md` are never candidates.
Anything under the effective Firstmate home's `projects/` directory and every repository's git history are outside the retention surface.

A regular file of at least 10 MiB below a closed task's `data/<id>/` directory is a large attachment candidate even when the task closed less than the age window ago.
Briefs and reports are excluded from attachment classification because their separate policies own them.
Open, queued, blocked, held, unresolved, duplicate, malformed, and persistent-secondmate records are retained regardless of age.

## Safety contract

Closure age comes from the checked task's single `(done YYYY-MM-DD)`, `(reported YYYY-MM-DD)`, or `(merged YYYY-MM-DD)` backlog completion marker when that record still exists.
The active backlog and `data/done-archive.md` are both consulted because `tasks-axi` archives older Done rows.
A task id present in an active section wins as not closed, even if inconsistent historical data also contains it.
Missing dates, duplicate closed rows, unsafe paths, ambiguous ownership, unreadable metadata, and live recorded endpoints retain every affected artifact and appear as `SKIP` lines.
When a workspace has aged out of both backlog files, its clock is the newer of its newest file modification time and newest checked-out commit time.
The preview and audit name `backlog closure`, `newest file mtime`, or `newest commit` for every workspace removal.
An orphan is considered a Firstmate task only when a durable brief exists or its id has Firstmate's generated task suffix, while other directories are reported as `non-task` and retained.

`bin/fm-landed-work-lib.sh` is the single owner of the dirty and landed-work predicates shared by teardown and retention.
Retention disables fetching while it evaluates that predicate, so stale local proof can only retain a workspace, never authorize deletion or change repository refs.
Each SDev repository is compared with the `default_base` declared for that exact repository in the SDev project registry.
SDev cleanup calls `sdev end --keep-branch`, and treehouse cleanup names one exact worktree to `treehouse destroy --yes` without any risky include flag.
At most ten SDev workspaces and ten treehouse worktrees are removed per run so the first apply is bounded and reviewable.
Files belonging to a task whose workspace is retained are also retained, except for independently size-qualified large attachments.

An apply run takes a per-home retention singleton and the same acquisition lock used to publish the session lock.
It exits without changing fleet records when a live Firstmate session owns the lock, while session start waits for an already-running bounded retention critical section instead of racing it.
The watcher is session-owned, so this exclusion also prevents retention from removing task records under a live watcher.

## Daily scheduling

macOS scheduling uses one per-home LaunchAgent generated by `bin/fm-retention-schedule.sh`.
Install it from the persistent Firstmate code root with `bin/fm-retention-schedule.sh install` after reviewing a dry run.
Inspect it with `bin/fm-retention-schedule.sh status`, and remove it with `bin/fm-retention-schedule.sh uninstall`.

The LaunchAgent starts at login and offers work once per hour.
`fm-retention.sh --apply --scheduled` records at most one completed apply run per local calendar day, so the hourly trigger is a first-opportunity retry after sleep, shutdown, or a live-session deferral rather than an hourly deletion policy.
The schedule is per `FM_HOME`, and the generated label includes a stable hash of that home.

## Audit and summary

Every completed apply run writes a timestamped audit to `data/retention/runs/`.
Each audit starts with the reclaimed total in human units, then records every removed path and every retained path with its reason.
`data/retention/latest-summary` contains only the plain captain-facing reclaimed-space and skipped-count sentence.
Session start surfaces that sentence without expanding the file listing, while the full audit remains available for targeted inspection.
`data/retention/last-run-date` owns the scheduled once-per-day completion marker.
